Home work 2: From Wallet Seed to Ethereum Address

Topic: Hashing, Key Derivation, and Cryptographic Primitives in Ethereum Wallets

1. Introduction & The Wallet Pipeline

Cryptocurrency wallets do not actually store digital coins or tokens, but they securely store cryptographic keys required to do transactions on the blockchain. The transformation from a human-readable pass phrase to a secure, checksummed Ethereum address follows a rigorous, multi-step deterministic pipeline:

Mnemonic (BIP-39) 
       ↓ 
Master Seed (PBKDF2-HMAC-SHA512) 
       ↓ 
HD Key Derivation (BIP-32 / BIP-44) 
       ↓ 
Private Key 
       ↓ (secp256k1 Elliptic Curve Multiplication) 
Public Key 
       ↓ (Keccak-256 Hash & Truncation) 
Raw Ethereum Address 
       ↓ (EIP-55 Mixed-case Checksum Encoding) 
Checksummed Ethereum Address

2. Standards and Cryptographic Primitives

  • BIP-39 (Bitcoin Improvement Proposal 39): Defines the creation of a human-readable mnemonic sentence (usually 12 to 24 words) mapped to an entropy pool, which is subsequently stretched using PBKDF2 (with HMAC-SHA512) to derive a binary 512-bit master seed.
  • BIP-32: Introduces Hierarchical Deterministic (HD) wallets. It allows a single master seed to deterministically generate an infinite tree of parent and child cryptographic key pairs using chain codes.
  • BIP-44: Builds directly on BIP-32 by establishing a logical standard derivation path structure for multi-account crypto wallets: m / purpose' / coin_type' / account' / change / address_index. For Ethereum, the coin type is hardcoded as 60'.
  • secp256k1: A specific Koblitz elliptic curve used for asymmetric public-key cryptography. It defines how a private key (random scalar) maps securely to a public key via elliptic curve multiplication, making it computationally infeasible to reverse.
  • Keccak-256: A cryptographic hash function belonging to the Keccak sponge family. Ethereum uses Keccak-256 (differing slightly from the final NIST SHA-3 standard padding convention) to distill public keys down to a unique 20-byte address identifier.
  • EIP-55 (Ethereum Improvement Proposal 55): A backward-compatible mixed-case checksum encoding scheme. By capitalizing specific letters based on the Keccak-256 hash of the address string, it protects users from typing or copy-pasting errors.

3. Core Cryptographic Distinctions

Concept Definition & Role in the Pipeline
Key Generation vs. Key Derivation Generation produces the primary root of trust from random or pseudo-random entropy sources (e.g., initial BIP-39 mnemonic creation). Derivation takes an existing master seed or parent key and uses deterministic math to generate child keys or sibling paths without needing further random input.
Public-Key Cryptography Asymmetric cryptography system relying on trapdoor mathematical functions (like secp256k1 ECDLP). It creates a key pair: a private key kept secret for signing transactions, and a public key shared openly to verify ownership and signatures.
Hashing A one-way mathematical function mapping data of arbitrary size to a fixed-size string or digest. In Ethereum, Keccak-256 ensures uniform distribution and avalanche properties when condensing public keys into address identifiers.
Checksums & Encoding Encoding translates raw binary data into readable text formats (like Hexadecimal). Checksums (like EIP-55) add redundancy rules into that encoding to catch human error or transmission slips instantly.

4. Temporal and Historical Context

Placing these underlying technologies into chronological perspective highlights how modern blockchain architecture builds upon decades of foundational cryptographic research:

  • 1977 — RSA: Introduction of asymmetric public-key cryptography, paving the way for secure digital communication and signatures.
  • 2001 — SHA-2 / SHA-512: Standardized by NIST as secure cryptographic hash standards widely adopted across internet security
